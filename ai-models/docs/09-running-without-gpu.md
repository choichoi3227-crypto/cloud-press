# GPU 없이 운영하기

## 1. 결론부터

**단계 1~2 규모(지금 이 저장소가 실제로 구현한 모델들)는 GPU 서버 비용 없이 완전히 운영 가능합니다.** 이건 이론이 아니라 이 저장소에서 실제로 검증된 사실입니다 — 지금까지 만든 Flash Texter(의도 분류 GRU)와 Nano-Tech Artist(조건부 GAN)는 전부 CPU만으로 학습과 추론을 마쳤습니다.

GPU가 정말로 필요해지는 시점은 로드맵 **단계 3**(자유 텍스트 생성 GPT류 모델, 텍스트→이미지 diffusion)부터입니다. 그 전까지는 GPU 서버를 임대할 필요가 없습니다.

## 2. 왜 지금 규모는 CPU로 충분한가

| 항목 | Flash Texter (단계 1) | Nano-Tech Artist (단계 1) | 참고: 단계 3 목표 |
|---|---|---|---|
| 파라미터 수 | 약 10~30만 개 | 약 300~600만 개 | 1억 개 이상 |
| 학습 데이터 규모 | 수백~수천 쌍 | 무제한 생성 가능(합성) | 수백억 토큰 |
| CPU 학습 시간 (로컬 검증 기준) | 30 epoch에 수 초~수십 초 | 소규모 데이터 기준 epoch당 수 초 | 수 주~수개월 |
| CPU 추론 응답 시간 | 수십 ms 이하 | 수십~수백 ms | 초 단위 이상 가능 |

이 저장소의 `inference-server`는 이미 `torch.cuda.is_available()`로 GPU 유무를 자동 감지해서, GPU가 없으면 CPU로 자동 폴백하도록 작성되어 있습니다 (`training/*/inference.py`의 `_device` 변수 참조). 즉 코드 수정 없이 그대로 CPU 서버에 배포하면 됩니다.

## 3. 완전 무비용 구성 (실제로 이 저장소로 가능한 조합)

```
학습:  Google Colab / Kaggle 무료 GPU (또는 로컬 CPU로도 가능, 단계 1 규모는 몇 분이면 끝남)
             │
             ▼
저장:  Hugging Face Hub 무료 티어 (모델 저장소 공개 시 무료)
             │
             ▼
추론 서버: Fly.io 무료 티어 또는 Railway 무료 티어 (CPU 전용 인스턴스)
             │
             ▼
API 게이트웨이: Cloudflare Workers 무료 티어 (하루 10만 요청까지 무료)
             │
             ▼
프런트엔드: Cloudflare Pages (무료, 무제한 정적 호스팅)
             │
             ▼
데이터베이스/캐시: Cloudflare D1 + KV 무료 티어
```

이 조합이면 **월 고정비 0원**으로 Flash Texter/Nano-Tech Artist 단계 1~2를 서비스할 수 있습니다. (트래픽이 각 서비스의 무료 티어 한도를 넘으면 그때부터 비용이 발생하지만, 이는 "성공해서 트래픽이 늘어난" 좋은 문제입니다.)

### 3.1 추론 서버를 위한 무료/저가 CPU 호스팅 옵션

| 서비스 | 무료 티어 | 비고 |
|---|---|---|
| Fly.io | 소형 VM 무료 할당량 제공 (정책은 변동될 수 있으니 배포 시 재확인) | Dockerfile 그대로 사용 가능 (`inference-server/Dockerfile`) |
| Railway | 월 일정 크레딧 무료 제공 | GitHub 연동 배포 간편 |
| Render | 무료 웹 서비스 티어 (유휴 시 슬립) | 첫 요청 시 재기동 지연(cold start) 있음 |
| 자체 저사양 VPS | 완전 무료는 아니지만 매우 저렴(월 몇 달러대) | 슬립 없이 상시 응답, 가장 안정적 |

**주의**: 무료 티어 대부분은 일정 시간 요청이 없으면 인스턴스를 슬립시킵니다. 슬립 상태에서 첫 요청이 오면 수 초의 지연(cold start)이 발생할 수 있습니다. `docs/01-architecture-detail.md` 3절에 설명한 대로, 이 경우 Worker가 503을 반환하고 "잠시 후 다시 시도"로 안내하거나, 헬스체크로 주기적으로 깨워두는 방식(예: 무료 크론 서비스로 5분마다 `/v1/health` 호출)을 쓸 수 있습니다.

## 4. GPU가 실제로 필요해지는 시점과, 그때도 비용을 줄이는 법

로드맵 단계 3(대규모 사전학습, diffusion 이미지 생성)에 도달하면 학습에는 GPU가 사실상 필수입니다. 이 시점에도 상시 GPU 서버를 유지할 필요는 없습니다.

- **학습**: 상시 GPU 서버 대신, RunPod/Vast.ai 같은 시간당 과금 GPU를 필요한 학습 기간에만 임대. 학습이 끝나면 인스턴스를 종료하면 되므로 "서버비"가 아니라 "학습에 쓴 시간만큼의 일회성 비용"이 됩니다.
- **추론**: 단계 3이라도 모델을 너무 키우지 않고 최적화(양자화, 지식 증류 등)하면 CPU 추론이 여전히 가능한 범위를 유지할 수 있습니다. 다만 이는 품질과의 트레이드오프이며, 실제로 필요해지는 시점에 재평가해야 합니다.
- **서버리스 GPU**: RunPod Serverless, Modal 같은 "요청이 올 때만 GPU를 켜는" 서비스를 쓰면, 상시 GPU 서버 비용 없이 트래픽에 비례해서만 과금됩니다. 다만 cold start 지연이 있습니다.

## 5. 지금 당장 확인할 수 있는 것

이 저장소의 추론 서버는 이미 CPU 환경에서 실제로 검증되었습니다 — `docs/08-roadmap.md`의 마일스톤 1 기록대로, 이 프로젝트의 모든 학습·추론·API 테스트가 GPU 없는 환경에서 수행되었습니다. 즉 "GPU 없이 작동하는가"는 가설이 아니라 이미 실증된 사실입니다. 배포 시에도 `inference-server`를 CPU 전용 인스턴스에 그대로 올리면 됩니다 — 코드 변경이 전혀 필요 없습니다.
